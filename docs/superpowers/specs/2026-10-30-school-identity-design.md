# 학생 식별을 학교 + 이름 + 뒤 4자리로 변경

## 배경과 결정

지금은 학생이 참여코드(수업) + 이름 + 휴대폰 뒤 4자리로 가입·로그인한다(조각 2, #13). 사용자 결정(2026-10-30)으로 **참여코드를 학생 가입·로그인에서 없애고 학교 + 이름 + 휴대폰 뒤 4자리**로 학생을 구분한다.

- 학교는 **자유 입력**이다. 서버가 공백·대소문자·유니코드 조합 차이를 정리해 식별 키로 쓴다. 학교 목록 등록은 하지 않는다.
- 학생은 가입 시 **수업에 속하지 않는다**(`classroom_id`는 비어 있다). 학생을 수업(단어장)에 배정하는 방법은 이후 작업에서 정한다. 교사의 수업 생성·참여코드 발급은 그대로 두며 학생 흐름에서만 쓰지 않는다.
- 교사 계정(이메일·비밀번호·교사 가입 코드)은 바뀌지 않는다.

## 식별 규칙

- 같은 학생 = 같은 `school_key` + 같은 `name_key` + 같은 뒤 4자리(PIN). 세 가지가 모두 같을 때만 중복 가입(409)이다.
- `school_key`: 보이지 않는 문자 제거 → 유니코드 NFC → **모든 공백 제거** → 소문자(`Locale.ROOT`). 비었거나 100자를 넘으면 거절(400). 표시용 `school`은 보이지 않는 문자 제거 → NFC → 연속 공백을 한 칸으로 → 앞뒤 공백 제거.
- `name_key`는 기존 규칙(`Names.key`) 그대로.
- PIN은 지금처럼 BCrypt 해시(`secret_hash`)로 저장하고, 같은 학교·이름의 계정을 모두 비교한다.
- 시도 제한 키: `student:<school_key>:<name_key>`. 선차감·성공 시 1회 환불 규칙은 그대로.
- 로그인 실패(401) 메시지: `학교, 이름 또는 휴대폰 번호가 올바르지 않아요.` 학교가 없는 경우도 같은 응답이며 BCrypt 비용 1회를 치른다.

## API

- `POST /api/auth/signup`, `POST /api/auth/login` 요청: `{ "school": "...", "name": "...", "phoneLast4": "1234" }`. `classCode`는 더 받지 않는다. 검증 오류 순서는 `school` → `name` → `phoneLast4`. 학교 메시지: `학교를 입력해 주세요`, `학교 이름은 100자 이하로 입력해 주세요`.
- `GET /api/users/me` 응답에 `school`(학생은 표시용 학교, 교사는 null)을 더한다. `classroom`은 그대로(학생은 지금은 null).

## 데이터베이스 (V7)

- `app_user`에 `school VARCHAR(100)`, `school_key VARCHAR(100)` 추가, 인덱스 `(school_key, name_key)`.
- 학생이 반드시 수업에 속해야 한다는 제약(`ck_app_user_student_classroom`)을 지우고, 대신 학생은 반드시 학교가 있어야 한다는 제약을 `NOT VALID`로 추가한다(학교가 없던 옛 개발용 학생 행은 검사하지 않고, 새 행부터 검사한다). 옛 학생 행은 새 로그인에 매칭되지 않으므로 다시 가입해야 한다.

## 알려진 한계와 위험 (사용자에게 알린다)

- **추측 난이도가 낮아진다.** 참여코드는 비공개에 가까운 값이었지만 학교·이름은 알려진 정보라서, 이름과 학교를 아는 사람은 4자리를 추측할 수 있다. 지금의 제한(키당 5회/5분)이면 한 학생 계정을 뚫는 데 이론상 약 일주일 이상 걸리지만 계정이 학교·이름 전체에 걸쳐 많아졌다. 완화(연속 실패 시 더 긴 잠금, 알림)는 이 작업의 범위 밖이며 후속 이슈로 둔다.
- 학교 표기가 달라지면(약칭 등) 다른 학교로 가입된다. 오타로 만든 계정은 같은 키로만 접근할 수 있다. 학교 목록 선택으로 바꿀 수 있다.
- 시도 제한 창은 키마다 메모리에 쌓인다(기존과 동일한 한계, 단일 인스턴스).
- 동시에 같은 (학교, 이름, PIN)으로 가입하는 경합으로 중복이 생길 수 있다(기존과 동일, 허용).
- 학생이 수업에 속하지 않으므로 수업 단어 조회는 배정 방법이 정해진 뒤에 붙인다. 앱의 학생 가입·로그인 화면(참여코드 입력)은 이 API 변경에 맞춰 별도로 바꿔야 한다.
