# 학생 회원 탈퇴 (이슈 #37)

이름·학교를 저장하는데 학생이 스스로 지울 방법이 없었다. 탈퇴 API를 더한다.

## API

`POST /api/me/withdraw` `{ "phoneLast4": "1234" }` → **204**

- 학생 토큰만 쓸 수 있다(교사 403, 비로그인 401, 번호 형식 오류·본문 없음 400). 이슈에는 `DELETE /api/me`로 적었지만, DELETE 본문을 못 싣는 클라이언트·프록시가 있어서 POST로 정했다.
- **본인 확인**: 번호 4자리를 다시 받아 BCrypt로 비교한다. 훔친 토큰만으로 계정이 지워지지 않게 하려는 것이다.
- 번호가 틀리면 **403** `번호가 올바르지 않아요.` 401을 쓰지 않는 이유: 앱이 401을 "로그인 만료"로 보고 토큰 갱신과 로그아웃을 시도하기 때문이다.
- **시도 제한**: 로그인과 같은 5회/5분(사용자별 키 `withdraw:{id}`, 선차감). 5번 틀리면 맞는 번호로도 429. 서버 메모리 기반이라 재시작하면 초기화된다.

## 지워지는 것 / 남는 것

- 지워짐: 계정, 북마크, 학생이 만든 개인 단어(`bookmark`·`word`의 `ON DELETE CASCADE`).
- 남음: 교사가 올린 수업 단어(소유자 없음)와 다른 학생의 계정·북마크, 수업.
- 같은 학교·이름·번호로 다시 가입할 수 있다(유니크 제약이 없다).
- 교사 계정은 서버 설정(`TEACHER_ACCOUNTS`)으로 관리하므로 이 API로 지우지 않는다(#30에서 회수 방법을 다룬다).

## 탈퇴 뒤 토큰

사용자가 없어지므로 액세스 토큰과 리프레시 토큰이 가리키는 사용자가 없다. 사용자를 읽는 모든 경로(`/api/users/me`, `/api/me/**`, `/api/auth/refresh`)가 401을 돌려주고, 같은 자격으로 로그인해도 401이다(테스트로 확인).

## 로그아웃과 토큰 폐기 (결정)

서버 쪽 로그아웃(리프레시 토큰 폐기)은 **하지 않는다.** 앱의 로그아웃은 기기의 토큰을 지울 뿐이고, 이미 발급된 리프레시 토큰은 만료(기본 14일)까지 서버에서 유효하다. 토큰을 폐기하려면 사용자별 토큰 버전 열을 추가하고 토큰에 담아 대조해야 하는데(마이그레이션 필요), 지금 위협(기기 분실 등)에 비해 비용이 크다. 필요해지면 그때 도입한다. 탈퇴·계정 삭제로는 토큰이 즉시 무력해진다.

## 사람이 판단할 것

- 개인정보 처리방침·수집 동의 화면이 필요한지(저장 항목: 학교, 이름, 번호 4자리 해시). 법률 검토가 필요한 부분이라 코드로 정하지 않았다.

## 앱

앱의 "회원 탈퇴"(내 정보, 번호 입력과 확인 절차 포함)는 ssen-app 후속 이슈로 만든다.
